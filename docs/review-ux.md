## 重い順の問題と直し方

### 1. スマホから印刷する人への案内がない(パソコンが前提になっている)【重い】
- 画面: 印刷(`14-print` 〜 `15-print-scroll3`)
- 使う人の多くはスマホで開く。でも案内は「印刷の画面で『実際のサイズ』をえらぶ」「パソコンなら PDF として保存」だけ。スマホ(iPhone・Android)の印刷画面には「実際のサイズ/100%」の選択が出ないことが多く、お年寄りはそこで止まる。家にプリンターがない人も多い。
- 直し方:
  - 印刷画面のいちばん上で「どれで印刷しますか」を2〜3択の大きなボタンにする: **「パソコンとプリンター」/「スマホとプリンター」/「コンビニで印刷」**。えらんだ道の案内だけを出す(1画面に案内を詰めこまない)。
  - スマホ: 「印刷の画面で、紙の大きさを A4 にして、『拡大・縮小しない』を選ぶ。選べないときは、まず1枚だけ印刷して 5cm を測る」と書く。
  - コンビニ: 「PDF を保存する → コンビニのアプリ(ネットプリントなど)に入れる → 印刷機で『等倍』をえらぶ」。いまの「PDFとして保存をえらぶとコンビニのコピー機でも印刷できます」だけでは、保存のあとどうするかが分からない。
  - 可能なら print.js 側で **PDF を作ってダウンロードできるボタン**(紙の大きさ 100% 固定)を足すと、スマホ・コンビニの道がずっと楽になる。
- 係: デザイン係(`js/ui-print.js`)、型紙係(`js/print.js` の PDF 出力を足すなら)

### 2. 「ためしに1枚」が脇役になっていて、いきなり全部印刷しやすい【重い】
- 画面: 印刷のいちばん下(`15-print-scroll3`)
- 案内には「1枚目の 5cm を測って、ちがえば設定を見なおす」とあるのに、いちばん目立つ紺のボタンは「5枚 印刷する」。お年寄りは目立つボタンを押す。設定がちがっていたら紙とインクを5枚むだにして、気落ちする。
- 直し方: 2段にする。
  1. 主ボタン「**まず1枚だけ印刷する**(5cm の四角つき)」
  2. 押したあと「5cm でしたか?」→「**はい、5cmだった** → のこり4枚を印刷(2枚目から)」/「いいえ、ちがった → 設定の見なおし方」
  - 「5枚 印刷する」で1枚目をまた刷らないよう、「2枚目から」を選べるようにする(printPages の pages.slice(1))。
- 係: デザイン係(`js/ui-print.js`)

### 3. 型紙の全体図の中の文字が小さすぎて読めない【重い】
- 画面: 型紙(`10-pattern`、タブレット `t3-pattern`)
- スマホでの実際の大きさを測ると、凡例「いちばん外の太い線…」9px、「縫い代 1cm つき」「できあがり 46×36cm」9px、内ポケットの「裏布 1枚(わ)」5px、「縫い代 1cm つき」4px。決まり(最小 20px)の半分以下。「大きく見る」を押しても 1.5 倍どまりで、部品名の下の小さい字はまだ読みにくい(`13-zoom-in`)。「わ」の字が横に寝ている(回転)のも読みにくい。
- 直し方:
  - 図の下にある「❶ 本体 表布1枚・裏布1枚…」の **部品の一覧は SVG から出して、ふつうの文字(HTML・20px 以上)で並べる**。図の中は大きな丸数字と部品名だけにする。
  - 凡例(線の見方)も図の外の HTML にし、線の見本を太く大きく。
  - 「わ」は寝かせず、まっすぐ立てて書く(図でも紙でも)。
- 係: 型紙係(`js/print.js` の `overviewSVG`)、デザイン係(`js/ui-pattern.js` で一覧を出す)

### 4. 作り方に、むずかしい手芸の言葉がそのまま出てくる。説明がない【重い】
- 画面: 作り方(`16-steps` `18-allsteps` `21-steps-*`)
- よい所: 「中表」を使わず「表どうしが内側」と書いてあるのはとてもよい。
- でも次の言葉は、手芸がはじめてのお年寄りには通じない(出てくる袋の例):
  返し口(ほぼ全部)・仮どめ(トート全部)・あき止まり(巾着・がま口)・合い印(はこ型・信玄袋)・まつる(ボストン・ボディバッグ)・**外表**(マルシェ・バルーン。「中表」を避けたのに、こちらは説明なしで出る)・ギャザー/あらい目のミシン(マルシェ・バルーン・グラニー)・バイアス/バイアステープ(めがね・エコ)・Dカン/送りカン/ナスカン(ショルダー・リュック)・接着芯・キルト芯・ダーツ(がま口)・ジグザグ縫い・コの字に縫う・三つ折り/四つ折り・押さえ縫い/縫いおさえ/ステッチ(3通りの言い方が混ざる)・むし(ファスナー)・耳(手ぬぐい)・目打ち・当て布
- 直し方:
  - 型紙係が「ことばの説明」の表を1つ作る(例: `js/bags/words.js` に `{ '返し口': '表に返すために、わざと縫わずに残しておく口' , … }`)。
  - デザイン係は、手順の文の中でその言葉に点線の下線をつけ、**押すと下に一言の説明が開く**ようにする(ポップアップより、その場で開くほうがお年寄りは迷わない)。
  - 言い方をそろえる: 「押さえ縫い/縫いおさえ/ステッチ」→「**ふちを縫いおさえる**」に統一。「バイアスでくるむ」→「バイアステープでくるむ」。「外表」→「裏どうしが内側になるように(外表)」。
  - 説明の例(前 → 後):
    - 返し口 → 返し口(表に返すために、縫わずに残しておく口)
    - 仮どめ → 仮どめ(ずれないように、縫い代の中を あらく縫っておく)
    - あき止まり → あき止まり(ここから上は縫わない、という印)
    - 合い印 → 合い印(2枚の布を合わせる目じるし。▲や切りこみ)
    - まつる → まつる(手ぬいで、表から見えないように小さく縫いとめる)
    - あらい目のミシン → ミシンの目をいちばん大きくして
    - ダーツ → ダーツ(布を三角につまんで縫い、丸みを出す所)
    - むしから5mm → ファスナーの歯(むし)から5mm
    - 耳 → 布のはしの、ほつれない所(耳)
- 係: 型紙係(`js/bags/*.js` の steps の文・ことばの表)、デザイン係(`js/ui-steps.js` の開く説明)

### 5. 「型紙を布に置いて、印を写す」手順が抜けている【重い】
- 画面: 作り方 1〜2(全部の袋)
- いまは「1. 型紙を印刷して貼り合わせ、いちばん外の線で切ります。2. 表布と裏布を切ります」と飛ぶ。そのあと「▲の印に合わせて」「前の印の所に」「合い印をそろえて」と、**布に印があるのが前提**で進む。初心者は布に印を写していないので、手順 6〜8 で必ず止まる。布目(矢印)の合わせ方もどこにも書いていない。
- 直し方: 全部の袋の手順 2 の前に、共通の1手順を入れる。
  - 例: 「型紙を布の裏に置き、矢印(布目)を布の耳と平行にして、待ち針でとめます。▲・●・切りこみの印を、チャコペンで布に写してから切ります。」
  - あわせて、手順の文の「印」は、型紙の紙の上の記号と同じ形(▲ ● ◆)を文に入れる。
- 係: 型紙係(`js/bags/*.js` の steps。共通文は `parts.js` に置くと30袋そろう)

### 6. 3D の上で指を動かすと、ページが下へ動かない(ほぼ1画面ぶんの「スクロールできない場所」)【中〜重い】
- 画面: 見る(`05-view`)。3D の場所は `touch-action: none` で、スマホでは縦 355px(画面の4割強)。ここを指でなぞるとバッグが回るだけで、下の「大きさ」「柄」へ進めない。マウスのホイールでは 3D が小さくなる(`06-view-scroll1` を撮ろうとしたら、絵が縮んだだけだった)。お年寄りは画面のまん中をなぞってスクロールしようとするので、「動かない、こわれた」と思いやすい。
- 直し方:
  - 3D は **横になぞったら回る/縦はページが動く**(`touch-action: pan-y` にして、横の動きだけ回す)。上下の傾きは要らないか、2本指だけにする。
  - ホイールでの拡大・縮小はやめる(ページのスクロールを優先)。
  - 3D のすぐ下に「下へ: 大きさと柄をえらぶ ⌄」の目じるしを出す。
- 係: 3D係(`js/viewer3d.js` の pointer/wheel)、デザイン係(`css/style.css` の `.stage`)

### 7. 柄や色をえらんでも、3D が画面の外にあって変わったのが見えない【中】
- 画面: 見る(`08-fabric-picked` `09-color-picked` → 上へもどして `09b-view-top-after`)
- 柄と色のボタンは 3D の 700px 以上下にある。押しても目の前は丸い見本が変わるだけで、バッグがどう変わったか分からない。何度も上下にスクロールすることになる。
- 直し方(どれか):
  - スマホでは、柄や色を押したら **画面の下に小さなバッグの絵(snapshot)を2秒ほど出す**。
  - または、3D を小さめ(縦 45vh まで)にして、そのすぐ下に「柄・色」を置き、「大きさ」は柄の下へ。
  - または、柄の場所までスクロールしたら 3D を上に小さく張りつける(sticky)。
- 係: デザイン係(`js/ui-view.js` `css/style.css`)

### 8. 言葉の途中で折り返す・カタカナの柄の名前が分かりにくい【中】
- 画面: 見る(`08b-fabric-scrolled`)、はじめの画面(`01-home` `02-home-scroll`)
- 柄の名前が「ヘリンボ/ーン」「ストライ/プ」「ギンガ/チェッ…」と、ことばの途中で切れる(ボタンの幅 92px に 20px の字)。仲間の名前も「ショルダー・な/なめがけ」と切れる。
- 柄の名前にカタカナが多い(ヘリンボーン・ギンガムチェック・リネン・デニム・ボーダー)。
- 直し方:
  - CSS で `word-break: keep-all` と、名前の幅を広げる(または2行まで、ことばの区切りで折る)。仲間の名前は「・」のあとで折る(`<wbr>` か、2つの span)。
  - 柄の名前(前 → 後): ヘリンボーン → **杉綾(すぎあや)** / ギンガムチェック → **こうし(ギンガム)** / ボーダー → **よこじま** / ストライプ → **たてじま** / リネン → **麻(リネン)**。デニムは通じる人が多いのでそのままでよい。理由: 70〜80代は和名のほうがなじみがあり、見本の絵と名前がすぐ結びつく。
  - 仲間の名前: 「ショルダー・ななめがけ」→「**かたかけ・ななめがけ**」(理由: ショルダーは「肩」の英語で、和語にすると短く折れにくい)。
- 係: 柄係(`js/fabric.js` の name)、型紙係(`js/bags/index.js` の GROUPS の name)、デザイン係(`css/style.css` の `.swatch .nm` `.gname`)

### 9. 一覧の説明文が3行で「…」と切れて、全部読めない【中】

### 10. 印刷した紙の上の字が小さい・言葉がむずかしい・字が切れる【中】
- 画面: 印刷ページ(`print-p1.png` `print-p2.png`)
- 紙の上の説明の字は 3〜3.7mm(9〜10ポイントくらい)、「布目(この向きを布のたて糸に)」「のりしろ A-2 をここに重ねて貼る」は 3mm で、しかも横に寝ていて灰色。老眼では読めない。下のふちの「左のふちを線で切り、A-1 の網かけに重ねて ◆ を合わせて貼る」もいちばん大事なのに小さい。
- 2枚目の右上「▲持ち手を付」が紙のはしで切れている(「付ける位置」の字がはみ出し)。
- 紙には「ぺたんこトート Mサイズ」「ぺたんこトート M」とあるが、画面は「中」。同じものなのに呼び名がちがう。
- 「網かけ」は通じにくい。
- 直し方:
  - 説明の字は 4.5mm(13ポイント)以上、灰色ではなく黒に近い色。寝かせる字は「のりしろ」の一言だけにして、説明はページ下のふちにまっすぐ書く。
  - 「Mサイズ」→「中(M)」、「M」→「中」。
  - 「網かけ」→「ななめ線のところ」。
  - 印の字(「▲持ち手を付ける位置」など)は、紙のはしで切れたら内側へずらす。
  - 「縫い代(1cm)が ついています」「太い線で 切って」のような途中のあきをなくす(13 も見てください)。

### 11. 貼り方の案内に「2枚目からは、ふちを切る」が書いていない【中】

### 12. 「用意するもの」に、型紙づくり・布切りの道具がない/布の名前に説明がない【中】

  - 布の名前の横に一言: 配色布 →「配色布(ポケットなどに使う、ちがう色の布。表布と同じでもよい)」、接着芯 →「接着芯(アイロンではって、布をしっかりさせる布)」。

### 13. 文の中の「単語の間のあき(スペース)」が、袋によってあったりなかったり【中〜軽い】
- 画面: 作り方・型紙・印刷の紙
- まいにちトート・ポーチ・和の袋は「表布と裏布を、本体の型紙で 2枚ずつ切ります。持ち手は 布に線を引いて 2本切ります。」とあきが多い。ぺたんこトート・リュックなどはあきがない。画面の見出し「布に直接 線を引いて切るもの」、紙の「太い線で 切って」「なら 正しく」も同じ。大きな字で折り返すと、行のはじめにあきが来て、字下げのように見える(`21-steps-po-gama`: 「線を お手持ちの口金」「ふちに そって」)。
- 直し方: あきをやめ、読点(、)と漢字で区切る。例(前 → 後):
  - 「布に直接 線を引いて切るもの」→「布に直接、線を引いて切るもの」
  - 「型紙の口の線を お手持ちの口金(15cm)に重ねて見ます」→「型紙の口の線を、お手持ちの口金(15cm)に重ねてみます」(「見ます」→「みます」: ためしにやる意味なので、ひらがなが正しい)
  - 「持ち手は 布に線を引いて 2本切ります」→「持ち手は、布に線を引いて2本切ります」
  - 理由: あきは、文がどこで切れるか分からなくなり、行のはじめに来ると字下げに見えるため。読点のほうが、どこで息をつくかがはっきりする。
- 係: 型紙係(`js/bags/tote.js` `pouch.js` `wa.js` ほか、`js/print.js`)、デザイン係(`js/ui-pattern.js` の見出し)

### 17. 紙の大きさ(A4/A3)を、印刷の画面で変えられない【軽い】
- 画面: 型紙 → 印刷
- A3 にするには、いったん「もどる」で型紙の画面の下までもどる必要がある。
- 直し方: 印刷画面の上に「A4で5枚/A3で2枚 [かえる]」を小さく出す。A3 は「家のプリンターがA3に対応しているときだけ。コンビニならA3でも印刷できます」と一言。
- 係: デザイン係(`js/ui-print.js`)

### 18. そのほか、袋ごとの文の小さな直し【軽い】
- スマホショルダー・めがねケース「前と後ろ+ふた」→「前と、後ろとふたがつながった布」(理由: 「+」は記号で、布が2枚なのか1枚なのか分からない)
- 巾着リュック 2「ほかのパーツも切ります」→ 切るものを全部書く(ふた・前ポケット・口布・手さげ・Dカン通し)(理由: 何を切るか分からないと先へ進めない。「パーツ」もカタカナ)
- お弁当袋 2「裏布をつけるなら、同じ型紙で 口だけ点線で切ります」→「裏布をつけるときは、同じ型紙で切ります。ただし口は、型紙の点線のところで切ります(表布より短くなります)」
- がま口 1 は「お手持ちの口金」が先に要る。いちばん上(手順の前)に「はじめに口金を買っておきます」と出すとよい。手順 10 の「目打ちで差しこみ」は手の力が要るので、すでにある「縫いつけ式の口金もおすすめ」をこの手順の中にも書く。
- ふたつきリュック 11「針14〜16号」→「ミシン針を、厚い布用(14〜16号)にかえて」
- 係: 型紙係(`js/bags/*.js`)

## よい所(このまま守ってほしい)
- 左上の大きな「もどる」がどの画面にも同じ場所にあり、押すと一つ前の画面に正しくもどる。作り方 → 型紙 → 見る、と迷わず帰れた(`19-back-from-steps` `20-back2`)。
- 白とクリーム地に紺の字で、差がはっきりしていて目にやさしい。見出しの明朝体が上品で、手づくりの本のような落ち着きがある。
- 3D のバッグがきれいで、柄と色の変化も分かりやすい(縫い目の点線まで出ていて手芸好きに響く)。
- 作り方が1手順ずつ大きな字(29px)で、「まえ/つぎへ」が大きい。どこまで進んだかを覚えていて、つづきから再開できる。
- 「中表」を使わず「表どうしが内側」と書いているのは、とてもよい配慮。
- 印刷の案内が「3つだけ」と数を先に言うので安心できる。絵(「実際のサイズ」を選ぶ絵、5cm を定規で測る絵)が分かりやすい。
- 紙の1枚目に 5cm の四角、◆の合わせ印、「わ(ここは布を折った線。切らない)」「このページは切らずに使います」と、紙の上にも説明がある。
- 長い持ち手を「布に直接線を引いて切る」にして紙の枚数を減らしているのは、実際の教室でもやるやり方で正しい。印刷が要らない袋には「印刷はいりません」と出る。
- 「かんたんなものだけ」の切りかえ、「前に見ていたバッグ」からのつづき、がま口の「手の力が弱い方は縫いつけ式も」の一言など、お年寄りへの心づかいがある。
- 寸法が「よこ・たて・マチ」と、ことばで書いてある。サイズの横に「A4の書類が入る」などの使いみちがあるのも、選びやすい。
